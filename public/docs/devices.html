Devices & Setup

Switch the microphone or camera at any time — even mid-set — without restarting the app.

Opening setup

Open the app menu in the control panel and choose Setup. The Connect Audio & Video dialog lets you pick which microphone and camera ahLOOKah should use.

Audio input

The selected microphone feeds the audio analysis that drives the visuals — the beat detection, frequency bands, and noise floor all come from here. Pick your interface, mixer feed, or built-in mic.

Camera input

The selected camera powers the Video FX patterns (chroma key, kaleidoscope, pixelate, trails, and more). It's only used when a camera-based pattern is playing.

Tip Don't see a device? Click Refresh Devices to rescan, and make sure the browser has permission for camera and microphone access.

Saving, opening and starting a project

Everything you save — pattern parameters, pad order, EQ and noise floor, screen calibration, projection layouts, device choices and panel state — is one project, stored in the browser you're using. The app menu manages it:

  • Save Project asks where to put the file and what to call it, then writes one .json (suggested name ahlookah-project-YYYY-MM-DD.json) containing all of it plus the identity of each linked directory (Custom Scripts, Node Patterns, Media). A browser without the save picker downloads the same file instead.
  • Open Project opens such a file here. It replaces the current browser's project, then shows a summary — reload to apply it. So save first if you want to keep what's already there, and finish or cancel any CUE before opening a project.
  • New Project clears this browser: every saved setting, all media patterns and every linked directory. It asks first, refuses while a CUE is staged, and keeps your device choices and setup state. Project files on disk are untouched.

On the same computer, a project's linked directories resume by themselves: linking a folder is remembered per project, so switching between projects never asks you to re-link what is already linked. Media files inside a linked directory are re-pointed automatically.

On another computer, the directories are unknown, and opening a project stops until each one is linked: a blocking dialog lists every missing Custom Scripts, Node Patterns and Media directory with a Link Folder button (and Reconnect when this computer remembers the directory but its access expired). The project only completes — summary and reload — once every directory has been linked. Folder names are hints, never identities, so the same name is required for each.

Media patterns travel as references only: their names and metadata are restored, but the image or video files stay on the original computer. When a file is not in the linked directory, its pattern is marked red in the library and on the pad, and Relink File appears in the parameters panel for it. Missing files never block a project — restore the files (or re-link the pattern) and it renders again. Scripts travel as names plus a fingerprint of their code: a project reopens the script files it lists whose bytes still match what it recorded, so your custom patterns come back without clicking anything. Anything edited, renamed or added since keeps the Open trusted script hint — the panel also says changed since this project was saved, or that the project recorded no fingerprint — and needs an explicit Open under Custom Scripts: a project file never carries code or trust. If the browser asks for folder access again at startup, Linked → Refresh renews it and finishes the reopen.

Note Device selections rarely match across machines, so if audio or camera stops working after opening a project, reopen Setup and pick the inputs for this computer. New Project intentionally keeps the device choices you already made here.
