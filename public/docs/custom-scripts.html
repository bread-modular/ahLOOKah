Custom Scripts

Build your own visuals in a real local folder. Edit with your favorite editor or coding agent, then explicitly reload them into ahLOOKah.

Before you begin: trusted code

JavaScript runs with the application's privileges. This is NOT a security sandbox. Only choose folders containing code you trust. Syntax checks catch mistakes, not malicious behavior or infinite loops. Back up your folder.

Use desktop Chrome on HTTPS or localhost. The feature checks for File System Access support and explains missing support instead of silently substituting uploads or a virtual filesystem. File access permission is separate from microphone/camera permission.

1. Choose your scripts folder

  1. In the pattern library, expand Custom Scripts.
  2. Click Choose folder, confirm that you trust its JavaScript, then select a real directory in Chrome's OS picker. Allow read/write access.
  3. Chrome saves a directory handle in this site's IndexedDB. No absolute path is exposed. The panel displays the directory name and permission status.

On subsequent visits, the last activated source snapshot is restored without reading your unsaved or externally edited files. If permissions expire, click Reconnect. If the folder moved or was deleted, choose it again. Denied permission does not erase last-good patterns.

2. Create and play your first pattern

Click Create script, enter a name, and a unique custom-name-unique.viz.js file is written directly into that directory. The starter is validated and activated. Click its pattern button to play; the Size slider updates the circle. No browser-only draft is created.

api.requireVersion(1);
api.create({
  id: 'custom-my-circle', name: 'My circle',
  params: [{key:'size', label:'Size', min:10, max:300, step:1, default:100}],
  draw({p, params}) {
    p.background(10); p.noStroke(); p.fill(90, 210, 255);
    p.circle(p.width / 2, p.height / 2, params.size);
  }
});

3. Edit externally, then Reload

Open the chosen directory in your editor or give that actual OS path to your coding agent. Edit guidance identifies the filename; it cannot launch a specific editor or reveal an absolute path. Change the color, save the disk file, then click Reload. Until Reload, the existing code keeps running. There is no filesystem watcher.

Only immediate *.viz.js files are scripts. Use classic strict JavaScript, not TypeScript/JSX or ES modules. Imports (including dynamic imports) are unsupported; bundle libraries into the same file. The folder may also contain assets such as PNGs and videos. Limits: 100 script files, 1 MB per file, 256 custom patterns.

4. Understand validation and rollback

Every candidate file is parsed and compiled before any candidate registration code executes. The app then validates metadata, hook types, numeric parameter/audio schemas, IDs and collisions before changing the registry. Unknown fields are rejected to catch typos. An invalid file rejects the whole folder reload: last-good registrations and renderers remain active. The panel names the file and failing field; syntax errors include the parser location. Correct it and Reload again.

Validation does not run every possible hook. JavaScript setup/draw exceptions, GLSL compilation failures, missing assets or arbitrary global side effects are not transactional. Runtime errors identify their file and hook; revert the file from your backup and Reload if needed. Never allocate timers, streams or listeners at the registration top level.

5. Use normal LIVE, CUE, output and cleanup

Custom patterns use the same VizCore engine as built-ins: Canvas2D, WebGL meshes and shaders, parameters, compact audio controls, media, embedded preview and output. VizCore is focused and not full p5.js. Drag a custom pattern to a pad slot, blend it with another, apply post-processing/screen mapping, or select it as a Projection Mapping child.

Shift-click stages CUE and Enter takes it LIVE. A successful script Reload/removal cancels CUE and pending TAKE, invalidates pending promotions, disposes old resources/audio and restarts affected output/preview. A brief interruption is intentional. Deleted selected IDs fall back to a built-in; missing projection children fall back to black. Camera patterns use the shared output camera; embedded preview shows the standard camera placeholder.

Each renderer gets its own state and an abort signal. Register timers/listeners/offscreen buffers with onCleanup, and honor cancellation after awaits. The host removes its canvas, media elements and GL contexts; scripts remain responsible for resources they allocate themselves. See the lifecycle example and API reference.

6. Try the capability examples

Save these files into your chosen scripts folder (not the application source tree), then Reload. Their IDs are distinct, so they can coexist.

  • Drawing: shapes, text, HSB, transforms, parameters, pixels and offscreen graphics.
  • WebGL meshes: box, sphere, cone and lighting.
  • GLSL shader: animated uniforms and offscreen texture.
  • Audio: capture-owner spectrum, continuous level and one-shot events.
  • Image: put photo.png in the folder; async loading, tint and compositing.
  • Video: put clip.mp4 in the folder; supported codec, muted playback, CUE pause/resume and cleanup.
  • Camera: allow/select a camera for shared output capture and mirroring.
  • CRUD and lifecycle: staged create/read/update/delete, timer/listener teardown.

7. Unload versus delete

Remove registrations unloads every pattern from that file but keeps the disk file; Reload restores it. api.delete(id) only deletes a staged registration owned by that script. Neither deletes disk content.

Delete file… asks for confirmation showing the filename, then permanently deletes the actual disk file and removes all its patterns. There is no undo/trash. External edits are also deleted. External file deletion is recognized on Reload. If disk deletion succeeds but browser storage fails, the error is reported; Reload reconciles the registry.

Troubleshooting and handing off to an agent

  • Unsupported / insecure: open desktop Chrome on HTTPS or localhost; no fallback is provided.
  • Permission denied: click Reconnect and allow read/write, or choose the moved folder again. Storage failures may require a persistent Chrome profile or freeing quota.
  • Filename / syntax / ID / hook error: edit the named file, use api.requireVersion(1), unique custom-… IDs and the exact schema; remove imports and Reload.
  • Blank or stalled visual: inspect the reported file/hook and Chrome console. Check renderer mode, GLSL logs, asset filename/codec and camera permission. Use a working example, then add changes incrementally.
  • Output differs temporarily: windows synchronize the activated source snapshot asynchronously and independently validate. Keep registration deterministic and avoid cross-window globals. Reload is not a distributed atomic show transition.

Give your agent the real folder path plus the complete Markdown API reference and checklist. Ask it to implement within those capabilities, clean up resources, save the file and tell you when to Reload. Test preview, LIVE, CUE/TAKE, output reopening, merge and mapping before a show. Settings export does not bundle scripts, handles or assets: back up/copy the OS folder separately.
