Nodes: build a pixel-composited pattern

Choose New Node Pattern in the main library’s Node Patterns category. The editor opens in place over the main view of the same browser window — no popup, no tab rail — and its toolbar Back to Main returns to the main app. It never claims the control/screen singleton or opens microphone/camera capture. A standalone ?role=nodes URL still works for direct links.

Build and connect

  1. Search the palette and drag a pattern into the workspace — clicking a palette row does not create nodes. Dragging an existing main-library pattern into the editor uses a validated cross-tab payload.
  2. Add a Blend, Color, Script or Audio node from the palette buttons above the pattern list. Blend and Color composite or filter images; Script produces numbers; Audio reports band activity.
  3. Click a visual source’s out ● port, then the destination’s ● base, ● layer, ● image (Blend/Color/Output) input. A new connection replaces that input’s previous connection. Cycles and output-as-source connections are rejected.
  4. Base is the lower image; Layer is composited over it. Choose Normal, Multiply, Screen, Overlay, Difference, or Add. Opacity controls the upper image. Blend outputs can feed further Blend/Color nodes; these are real canvas pixels, not CSS overlays.
  5. Connect the final image to the one Output node. Select any node to see its animated preview. Selected Pattern parameters are editable in the inspector. Select a Blend to edit its mode and opacity.

Color and Script nodes, and legacy Math nodes

Color takes one image input and writes a filtered image: saturation → brightness → contrast → hue-rotate, in that fixed order. Identity defaults (1 / 1 / 1 / 0) copy the input pixels exactly, including alpha. Its four sliders are ordinary numeric parameters, so they can be audio/math/script mapped like Pattern and Blend.

Math (legacy) is still loaded, edited, rendered and saved for pattern files that already contain it, but it is not created any more: there is no + Math palette button, and new graphs use Script instead. A legacy Math node keeps its full contract — add, subtract, multiply, divide, minimum, maximum, clamp and absolute over inputs a, b and c. c exists only for clamp: every other operation hides and disables that row, a wire left on the inactive port is removed when the operation changes, and the stored literal is kept for when clamp returns. Existing files are never converted to Script and nothing is dropped from them. The runtime never reads or traverses an inactive port. Each port accepts one wire from an Audio/Math/Script output; an unwired port uses its inspector literal. Values stay signed floats — nothing is normalized inside the graph. Division by zero and non-finite results fall back to 0 and show a diagnostic on the node.

Script turns a numeric source into a scalar output using one of two languages, chosen in the inspector. New Script nodes start in Body (statements + return):

let shape = sin(time) * 0.5 + 0.5;
if (x < 0.2) return 0;
const scaled = clamp(x * 2, 0, 1);
return lerp(scaled, shape, y);

The body is a small, checked JavaScript subset with the read-only inputs x, y, time (seconds) and the constants pi, e, tau: let/const declarations (one name each, with an initializer), plain and compound assignment to those locals (an assignment expression evaluates to the value it stores, a declaration statement discards it), blocks, if/else, early return, comparisons (== != === !== < <= > >=), short-circuiting && / ||, !, the ternary ?:, + − × ÷ %, parentheses and the listed math functions (sin cos tan asin acos atan atan2 abs min max floor ceil round sqrt pow exp log sign hypot clamp lerp, at most 3 arguments). Scope is lexical: a let/const belongs to the block it is declared in, an inner block may shadow an outer name but one block cannot declare the same name twice, and the whole block’s declarations are known before it runs — reading or assigning a name before its own declaration is an error, so let a = a + 1;, return a; let a = 1; and let a = 1; { let a = a + 1; } all fail. The inputs, constants and function names are reserved and read-only (x = 1; and let x = 1; are rejected). Comparisons and ! yield 1/0, never booleans; && and || short-circuit and evaluate to one of their operands, so x || 0.5 works as a default. The returned value must be a finite number. Loops, functions/arrows/classes, objects/arrays, property access, new, this, template literals, await/yield, imports, var, destructuring, spread, ++/--, the comma operator, with and debugger are rejected, and every global (window, document, process, globalThis, eval, Function…) is an unknown name.

The legacy Expression (single value) language is the original one-liner: numbers, x, y, time, pi, e, + − × ÷ %, unary minus and parentheses plus the same math functions, and nothing else. Graphs saved before the body language existed carry no language field and keep running as expressions, unchanged.

The source is never executed as JavaScript: Acorn parses it, every syntax node must pass an allowlist, and a body compiles once into a bounded instruction list that the editor’s own interpreter runs — no eval, no generated code, no property or global access. Bodies are limited to 1024 characters, 512 syntax nodes, 80 statements, 512 instructions, 32 locals, 12 nested block levels and an operand nesting depth of 16; expressions stay at 256 characters, 64 operations and depth 12. A body must contain a return, and its result is a function of the inputs alone — every evaluation starts from fresh locals. Sources that fail validation cannot be applied or saved; division/modulo by zero, a missing runtime return, non-finite results and other runtime errors fall back to 0 with a visible message. Compilation happens when a source is applied, never while frames render.

Press Ctrl+Enter (or click Apply) to validate, store and approve the text in the Script source box; plain Enter adds a new line, so bodies are multi-line. Unapplied text is never dropped silently: Save and Reload from Disk confirm before discarding it, and a failed Apply leaves the last applied source running. Script text travels inside the pattern file, but trusting it does not: a disk-loaded source must be reviewed and Applyed in this browser before it runs, and the approval is bound to that exact text and language (editing one character, or switching languages, invalidates it). Approvals live in browser storage, so an imported file can never carry a trust flag with it.

Editing controls

Drag node headers to move them. A focused header also moves with arrow keys (10 px). Ctrl/Command-click headers or drag a marquee to select a group. Delete/Backspace removes all selected Pattern, Blend, Color, Audio, Math and Script nodes, including their incident image wires, scalar wires and mappings. Required Output is kept, even when selected with other nodes; its unrelated connections survive. Editing text or inputs never deletes nodes. Clicking a wire or a ◇ signal endpoint selects that connection on its own — its endpoint nodes are not selected, and Delete/Backspace (or the sidebar Delete connection button) then removes only that wire while both nodes survive. Deleting lives on the graph itself rather than in the inspector: there are no Delete node or Disconnect buttons to reach for, so clicking a node selects nodes and clears the connection selection, and group deletion is unchanged. Wires that share both endpoints are bowed apart so each one stays visible and clickable. Escape cancels a pending connection. The workspace scrolls to accommodate larger graphs.

Audio modulation

Add multiple Audio nodes and choose bass, mid or high. Their activity is the same default custom-script reactive feature normalized by response() to 0…1, not raw FFT or a new sensitivity curve. Keep the control window’s audio enabled: the editor and saved patterns consume its shared compact audio controls — the same document runtime when the editor is opened from the main app, the bus otherwise — never a second microphone. Missing/stale input settles to zero; no fabricated idle beats. Math and Script outputs are signals too: they can wire into other Math/Script inputs and into any numeric parameter.

  1. Click an Audio/Math/Script out ● port, then a Pattern/Blend/Color violet ◇ signal endpoint, or a Script ● x/y input port for scalar wiring (legacy Math nodes still expose ● a/b, plus ● c for clamp). Repeat to fan out. Dashed violet wires are signals; solid image wires remain separate.
  2. Drag a connected signal chip from the inspector onto a numeric slider to map it; dropping a second signal on the same slider replaces the existing mapping after confirmation. Selecting a ◇ endpoint or a dashed wire selects that connection (the sidebar names it) without selecting its nodes. One signal can drive many parameters/nodes; each parameter has one mapping.
  3. The saved-base thumb is hidden while mapped; a distinct pale-yellow LIVE marker and numeric value show the effective runtime value throughout. Removing the mapping restores the base thumb and its saved value. The violet box overlays the slider track: drag its body to move the range, or its endpoints to resize it. The controls below a mapped slider start collapsed and have no heading or button of their own — click the overlay on the track, or focus it and press Enter/Space, to reveal or hide the Mapping min/max fields, Signal in min/max and Remove mapping. A compact pill beside the parameter’s name (for example Audio · high or Script) names the connected signal, resolved live from the graph, so a band change or a remap updates it; it rides the title row and stays visible whether the controls are open or collapsed. Swapping a range is a plain field edit: type the lower bound into Mapping max and the higher one into Mapping min, and the sweep runs in reverse. Dragging the box or a handle collapses the panel and a release after a resize never opens it again, so moving the range cannot be mistaken for a click. Min means the signal’s low bound and max its high bound (reversed ranges are valid). Both mapping endpoints accept any finite value, including values outside the parameter’s own range: a negative minimum is stored and saved exactly as typed rather than being reset to the parameter floor, and only the value the parameter actually consumes is clamped to its domain, so the sweep shifts instead of losing the endpoint. The Signal in min/max fields convert a different input range and accept negative ranges (for example −2…0.5): a Math or Script output of 0…4 can drive the full parameter range, and older mappings keep the default 0…1; a range needs its max strictly above its min. Base values remain stored and unchanged during playback; removing modulation restores them.

Pattern numeric sliders, Blend opacity and Color parameters are supported. Enum/bool/text controls are not; Output has no numeric control. Audio, Math and Script nodes use no visual renderer or canvas. Nodes, image wires, scalar wires (including unassigned endpoints), each Script source with its language (absent means the legacy expression language) and mapping ranges persist in .nodes.json; existing version-1 graphs still open and keep their mappings. Deleting a node removes its image wires, scalar wires and mappings. Nested graphs are not supported.

Disk patterns, drafts, LIVE and CUE

In the main UI, expand Node Patterns. Use desktop Chrome on HTTPS or localhost. Link Folder grants access to a folder, remembers its handle, and loads its top-level .nodes.json patterns. Refresh folder rereads disk, discovers additions/removals/edits, and requests expired read permission from your click. Background tabs never request permission. Invalid or inaccessible files are reported and excluded, not resurrected from browser storage.

Open Pattern uses the native disk picker and validates a file before adding it to the main library. Files opened outside the linked folder also appear in the main library and reconnect after reload. Linking a folder clears that explicit outside-file selection, without deleting files. Select a node pattern in the main library, then click Edit Pattern in its sidebar. The editor reads that exact graph from disk using its repository ID, in this window. Missing, invalid or inaccessible files show a loading error instead of a different graph. Use Retry loading to renew permission. New Node Pattern opens a fresh editor; only one graph is edited at a time.

Save writes a complete pattern into the linked folder. New drafts use a sanitized graph name plus .nodes.json; a pattern loaded from that folder keeps its filename even when renamed in the editor. An outside file is copied into the linked folder on Save, never overwritten at its original location. Existing destination files require confirmation. A file changed/deleted since it was opened cannot be overwritten: open it again first. Same-origin saves use Web Locks and recheck disk content; unrelated external applications do not participate in that lock, so avoid simultaneous external writes.

Drafts are in-memory for the single open editor session and never broadcast edits to LIVE. Save before closing/reloading. Back to Main, Reload from disk, and any dirty-graph replacement warn before discarding unsaved work; nothing is retained as a hidden second draft, so reopening loads the saved graph. Picker cancellation, permission denial and failed writes leave the draft available. There is no revisions, import/export or browser pattern library UI.

Saved/opened patterns appear in Node Patterns in same-origin main-app tabs. Click to play LIVE; Shift-click stages CUE; ordinary pads and merge remain supported. A confirmed overwrite updates the same pattern ID, including LIVE when selected, and invalidates staged runtimes. Disk refreshes broadcast notifications to other tabs, which reread their handles. No polling, server library or cloud sync is used. IndexedDB stores only folder/file handles and identity preferences; graph contents are read from disk. Old browser-only records are ignored, not automatically deleted or migrated.

Source support and dependencies

  • Built-in Canvas2D/WebGL patterns, local image/video media, custom scripts, and projection patterns reuse the existing source runtime contract. New source nodes snapshot saved main-app parameter values (or defaults); edit the source node’s numeric geometry/child parameters in the inspector as needed.
  • Camera nodes show a visible explanation in editor/control previews. Only an output runtime with the existing shared camera source can render them; graph nodes do not create a second capture owner.
  • Output/control runtimes expose each leaf’s independent audio-control slot, parameter snapshot and lifecycle to the existing capture owner. The editor uses the main window’s shared controls for both ordinary audio-reactive patterns and mapped parameters. It does not capture a separate microphone.
  • Graph-in-graph sources are deliberately disallowed, including graph children hidden inside projection definitions. Flatten the composition into ordinary source and Blend nodes instead.
  • Missing sources, source failures and unavailable projection compositors have visible diagnostics. Media renderers retain their existing missing-file/permission placeholders. Relink files/grant permissions in the main media library, then reload the draft.

Pattern file format and dependencies

Files contain format: "viz2-nodes", version: 1, a graph, numeric parameter snapshots and a dependency manifest. Reads validate version, byte size, references, ports, cycles, parameters and limits before loading. Folder files must be complete, with the Output-connected branch wired.

A graph carries three independent link kinds: image edges, scalar signalEdges (from/to/port into Math/Script inputs) and terminal modulations (a signal source, an optional target parameter and its output range plus the optional inputMin/inputMax signal range). One wire per input, fanout allowed, cycles rejected.

Media bytes, file handles, executable scripts and external assets are not embedded. The destination must have matching dependencies. Custom-code fingerprints and projection topology/parameter definitions detect changed dependencies rather than silently substituting them. File content is never executed as code. Restore dependencies in the main app or choose Refresh dependencies to accept current local definitions, then Save. Media content itself is not content-addressed: a relinked file under the same media ID can differ.

Resource bounds and implementation

No node, Pattern-source or wire budget is imposed: node count, source count and wiring are limited only by the machine that edits and renders the graph, so the practical size follows your hardware. What validation still bounds is structural and safety: references, ports, uniqueness, cycles, finite numbers, the restricted script source (256 characters for expressions, 1024 for bodies), and 200 KB per JSON record/file so a single pattern stays loadable. Folder bookkeeping keeps 64 folder patterns and up to 64 explicitly opened files. Internal graph images are capped to 1280×720 (aspect ratio preserved) and scaled to the output size. Unconnected draft branches may render for inspection; only the Output-connected branch must have all inputs connected to save. Empty input ports are transparent while drafting.

Each source is captured immediately after its draw (including async draws), before WebGL discards the frame. Every graph owns buffers, source instances, parameter objects and disposal/resize handling. Move/rename operations do not restart previews; parameter/topology changes currently rebuild the editor preview, so videos and temporal effects restart on those edits. Blend operations use browser Canvas2D sRGB compositing and Color uses Canvas2D filters with identity defaults short-circuited to a plain copy; neither is Photoshop’s complete color-management pipeline. Scalar values are computed once per rendered frame and shared by every consumer (sidebar readout, preview, LIVE and CUE); audio capture and output ownership are unchanged.

Code lives in src/nodes/ (definitions.js, geometry.js, scalar.js, script.js, script-core.js, script-body.js, script-approval.js). Wire endpoints come from geometry.js, which mirrors the CSS node metrics, so the socket a wire lands on is measured geometry rather than a hand-written node-height offset. Tests: PLAYWRIGHT_PORT=5186 npx playwright test tests/nodes.spec.js tests/nodes-scalar.spec.js tests/nodes-script-body.spec.js tests/nodes-wire-selection.spec.js. Node pattern files are separate from general settings. Move/copy them using your file manager, then link the destination folder. The body language’s instruction budgets and limiting behaviour are covered by tests/nodes-script-body.spec.js, which also reports a single indicative compile/evaluation time measurement — it makes no comparative performance claim.
