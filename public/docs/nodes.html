Nodes: build a pixel-composited pattern

Open Open Nodes editor ↗ above the main pattern library. The editor runs in a separate ?role=nodes tab, without claiming the control/screen singleton or opening microphone/camera capture.

Build and connect

  1. Search the palette and drag a pattern into the workspace (or click it). Dragging an existing main-library pattern into the editor uses a validated cross-tab payload.
  2. Add one or more Blend nodes. Click a source’s out ● port, then the destination’s ● base, ● layer, or Output’s ● image. A new connection replaces that input’s previous connection. Cycles and output-as-source connections are rejected.
  3. Base is the lower image; Layer is composited over it. Choose Normal, Multiply, Screen, Overlay, Difference, or Add. Opacity controls the upper image. Blend outputs can feed further Blend nodes; these are real canvas pixels, not CSS overlays.
  4. Connect the final image to the one Output node. Select any node to see its animated preview. Selected Pattern parameters are editable in the inspector. Select a Blend to edit its mode and opacity.

Editing controls

Drag node headers to move them. A focused header also moves with arrow keys (10 px). Select and press Delete/Backspace, or use Delete node. Output cannot be deleted. Click a wire or an inspector Disconnect button to remove a connection; focused wires support Enter/Delete. Escape cancels a pending connection. The workspace scrolls to accommodate larger graphs.

Drafts, revisions, LIVE and CUE

Drafts live only in the editor tab’s session storage, survive reload, and never broadcast parameter edits or change LIVE. New draft and Load draft replace the current draft. Export first if you want to keep an unsaved alternate.

Save revision writes a new immutable ID every time. Saved revisions appear in the app’s ordinary Node Graphs library group in every same-origin tab. Click there to play LIVE; Shift-click stages CUE using the existing application workflow. Graphs can also occupy ordinary pattern pad slots and participate in the existing two-pattern merge.

Each selection ID pins one graph revision, including its own parameter values. Saving or loading a draft never updates an already-selected revision. Choose the new revision explicitly to use it. A separate localStorage record per revision avoids cross-tab lost-update races; BroadcastBus notifications plus storage events refresh the library. There is no server library or cloud sync.

Source support and dependencies

  • Built-in Canvas2D/WebGL patterns, local image/video media, custom scripts, and projection patterns reuse the existing source runtime contract. New source nodes snapshot saved main-app parameter values (or defaults); edit the source node’s numeric geometry/child parameters in the inspector as needed.
  • Camera nodes show a visible explanation in editor/control previews. Only an output runtime with the existing shared camera source can render them; graph nodes do not create a second capture owner.
  • Output/control runtimes expose each leaf’s independent audio-control slot, parameter snapshot and lifecycle to the existing capture owner. The standalone editor uses its synthetic idle preview audio, not live microphone capture.
  • Graph-in-graph sources are deliberately disallowed, including graph children hidden inside projection definitions. Flatten the composition into ordinary source and Blend nodes instead.
  • Missing sources, source failures and unavailable projection compositors have visible diagnostics. Media renderers retain their existing missing-file/permission placeholders. Relink files/grant permissions in the main media library, then reload the draft.

JSON portability

Export JSON produces format: "viz2-nodes", version: 1 with the graph, numeric parameter snapshots and a dependency manifest. Import validates version, size, references, ports, cycles, parameters and limits before replacing a draft; it does not auto-save or change LIVE.

Media bytes, file handles, executable scripts and external assets are not embedded. The destination must have the matching dependencies. Custom-code fingerprints and projection topology/parameter definitions detect changed dependencies rather than silently substituting them. Imported code is never executed. Restore dependencies in the main app or choose Refresh dependencies to explicitly accept current local definitions, then save a new revision. Media content itself is not content-addressed: a relinked file under the same media ID can differ.

Resource bounds and implementation

Limits: 24 nodes, 8 leaf renderers including projection surfaces, 48 wires, 200 KB per JSON record/file, 64 immutable saved revisions. Internal graph images are capped to 1280×720 (aspect ratio preserved) and scaled to the output size. Unconnected draft branches may render for inspection; only the Output-connected branch must have all inputs connected to save. Empty input ports are transparent while drafting.

Each source is captured immediately after its draw (including async draws), before WebGL discards the frame. Every graph owns buffers, source instances, parameter objects and disposal/resize handling. Move/rename operations do not restart previews; parameter/topology changes currently rebuild the editor preview, so videos and temporal effects restart on those edits. Blend operations use browser Canvas2D sRGB compositing; this is not Photoshop’s complete color-management pipeline.

Code lives in src/nodes/. Tests: PLAYWRIGHT_PORT=5186 npx playwright test tests/nodes.spec.js. Graph JSON export is separate from the app’s general settings export; export graphs explicitly when moving libraries.
