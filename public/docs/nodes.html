Nodes: build a pixel-composited pattern

Choose New Node Pattern ↗ in the main library’s Node Patterns category. The editor runs in a separate ?role=nodes tab, without claiming the control/screen singleton or opening microphone/camera capture.

Build and connect

  1. Search the palette and drag a pattern into the workspace — clicking a palette row does not create nodes. Dragging an existing main-library pattern into the editor uses a validated cross-tab payload.
  2. Add one or more Blend nodes. Click a source’s out ● port, then the destination’s ● base, ● layer, or Output’s ● image. A new connection replaces that input’s previous connection. Cycles and output-as-source connections are rejected.
  3. Base is the lower image; Layer is composited over it. Choose Normal, Multiply, Screen, Overlay, Difference, or Add. Opacity controls the upper image. Blend outputs can feed further Blend nodes; these are real canvas pixels, not CSS overlays.
  4. Connect the final image to the one Output node. Select any node to see its animated preview. Selected Pattern parameters are editable in the inspector. Select a Blend to edit its mode and opacity.

Editing controls

Drag node headers to move them. A focused header also moves with arrow keys (10 px). Select and press Delete/Backspace, or use Delete node. Output cannot be deleted. Click a wire or an inspector Disconnect button to remove a connection; focused wires support Enter/Delete. Escape cancels a pending connection. The workspace scrolls to accommodate larger graphs.

Audio modulation

Add multiple Audio nodes and choose bass, mid or high. Their activity is the same default custom-script reactive feature normalized by response() to 0…1, not raw FFT or a new sensitivity curve. Keep the main control window open with audio enabled: the editor and saved patterns consume its shared compact audio controls, never a second microphone. Missing/stale input settles to zero; no fabricated idle beats.

  1. Click Audio’s out port, then a Pattern or Blend’s violet ◇ signal endpoint. Repeat to fan out. Dashed violet wires are modulation; solid image wires remain separate.
  2. Select the endpoint or dashed wire. Choose a numeric target and Map / replace parameter, or drag a connected signal chip onto a numeric slider. Replacing an occupied parameter asks for confirmation. One signal can drive many parameters/nodes; each parameter has one mapping.
  3. The violet box overlays the base slider: drag its body to move the range, or its endpoints to resize it. Keyboard users can edit the labeled Mapping min/max number fields, Reverse range, and Start at base. Min means signal 0 and max means signal 1 (reversed ranges are valid). Values clamp and snap to the parameter step. Base values remain stored and unchanged during playback; removing modulation restores them.

Pattern numeric sliders and Blend opacity are supported. Enum/bool/text controls are not; Output has no numeric control. Audio nodes count toward the 24-node graph limit but use no visual renderer or canvas. Nodes, links (including unassigned endpoints), and mapping ranges persist in .nodes.json; existing version-1 graphs still open. Deleting a node removes its signal links. Nested graphs are not supported.

Disk patterns, drafts, LIVE and CUE

In the main UI, expand Node Patterns. Use desktop Chrome on HTTPS or localhost. Link Folder grants access to a folder, remembers its handle, and loads its top-level .nodes.json patterns. Refresh folder rereads disk, discovers additions/removals/edits, and requests expired read permission from your click. Background tabs never request permission. Invalid or inaccessible files are reported and excluded, not resurrected from browser storage.

Open Pattern uses the native disk picker and validates a file before adding it to the main library. Files opened outside the linked folder also appear in the main library and reconnect after reload. Linking a folder clears that explicit outside-file selection, without deleting files. Select a node pattern in the main library, then click Edit Pattern in its sidebar. A separate browser tab reads that exact graph from disk using its repository ID. Missing, invalid or inaccessible files show a loading error instead of a different graph. Use Retry loading to renew permission. New Node Pattern opens a fresh editor tab.

Save writes a complete pattern into the linked folder. New drafts use a sanitized graph name plus .nodes.json; a pattern loaded from that folder keeps its filename even when renamed in the editor. An outside file is copied into the linked folder on Save, never overwritten at its original location. Existing destination files require confirmation. A file changed/deleted since it was opened cannot be overwritten: open it again first. Same-origin saves use Web Locks and recheck disk content; unrelated external applications do not participate in that lock, so avoid simultaneous external writes.

Drafts are in-memory, per-tab, and never broadcast edits to LIVE. Save before closing/reloading. New draft, Reload from disk, and leaving a dirty editor warn before discarding unsaved work. Picker cancellation, permission denial and failed writes leave the draft available. There is no revisions, import/export or browser pattern library UI.

Saved/opened patterns appear in Node Patterns in same-origin main-app tabs. Click to play LIVE; Shift-click stages CUE; ordinary pads and merge remain supported. A confirmed overwrite updates the same pattern ID, including LIVE when selected, and invalidates staged runtimes. Disk refreshes broadcast notifications to other tabs, which reread their handles. No polling, server library or cloud sync is used. IndexedDB stores only folder/file handles and identity preferences; graph contents are read from disk. Old browser-only records are ignored, not automatically deleted or migrated.

Source support and dependencies

  • Built-in Canvas2D/WebGL patterns, local image/video media, custom scripts, and projection patterns reuse the existing source runtime contract. New source nodes snapshot saved main-app parameter values (or defaults); edit the source node’s numeric geometry/child parameters in the inspector as needed.
  • Camera nodes show a visible explanation in editor/control previews. Only an output runtime with the existing shared camera source can render them; graph nodes do not create a second capture owner.
  • Output/control runtimes expose each leaf’s independent audio-control slot, parameter snapshot and lifecycle to the existing capture owner. The standalone editor uses its synthetic idle preview audio, not live microphone capture.
  • Graph-in-graph sources are deliberately disallowed, including graph children hidden inside projection definitions. Flatten the composition into ordinary source and Blend nodes instead.
  • Missing sources, source failures and unavailable projection compositors have visible diagnostics. Media renderers retain their existing missing-file/permission placeholders. Relink files/grant permissions in the main media library, then reload the draft.

Pattern file format and dependencies

Files contain format: "viz2-nodes", version: 1, a graph, numeric parameter snapshots and a dependency manifest. Reads validate version, byte size, references, ports, cycles, parameters and limits before loading. Folder files must be complete, with the Output-connected branch wired.

Media bytes, file handles, executable scripts and external assets are not embedded. The destination must have matching dependencies. Custom-code fingerprints and projection topology/parameter definitions detect changed dependencies rather than silently substituting them. File content is never executed as code. Restore dependencies in the main app or choose Refresh dependencies to accept current local definitions, then Save. Media content itself is not content-addressed: a relinked file under the same media ID can differ.

Resource bounds and implementation

Limits: 24 nodes, 8 leaf renderers including projection surfaces, 48 wires, 200 KB per JSON record/file, 64 folder patterns and up to 64 explicitly opened files. Internal graph images are capped to 1280×720 (aspect ratio preserved) and scaled to the output size. Unconnected draft branches may render for inspection; only the Output-connected branch must have all inputs connected to save. Empty input ports are transparent while drafting.

Each source is captured immediately after its draw (including async draws), before WebGL discards the frame. Every graph owns buffers, source instances, parameter objects and disposal/resize handling. Move/rename operations do not restart previews; parameter/topology changes currently rebuild the editor preview, so videos and temporal effects restart on those edits. Blend operations use browser Canvas2D sRGB compositing; this is not Photoshop’s complete color-management pipeline.

Code lives in src/nodes/. Tests: PLAYWRIGHT_PORT=5186 npx playwright test tests/nodes.spec.js. Node pattern files are separate from general settings. Move/copy them using your file manager, then link the destination folder.
